# Mont Forge 开发流水线

把 mont-forge 的 44 个工程技能编排成一条**可调用**的开发流水线。技能是「说明书」，本插件是「流水线工位」：模型在开发一个系统的全流程中，每个阶段直接调用对应工具，拿到阶段目标、要加载的技能、步骤、产物模板与退出标准。

## 为什么不是又一个技能

技能需要模型自己判断该不该加载；工具是函数调用，出现在工具列表里，模型可以直接调。这套插件解决的是「用户说了一句话，模型不知道该用 44 个技能里的哪个」的问题：不用记技能名，记阶段就行。

## 六个阶段

| 阶段 | 工具 | 产出 |
|------|------|------|
| 需求 → 规格 | `forge_spec` | 规格文档、验收标准、非目标、质量门槛 |
| 规格 → 计划 | `forge_plan` | 任务清单、阻塞边、关键路径、首个小切片 |
| 实现 | `forge_build` | 可运行的小切片与对应测试 |
| 验证 | `forge_verify` | 复现记录、根因、回归测试、验证证据 |
| 评审 | `forge_review` | 五轴结论、分级问题清单、必修复项 |
| 交付 | `forge_ship` | 提交历史、CI 结果、文档、监控、回滚预案 |

## 辅助工具

- `forge_assess` — 扫描项目目录，报告技术栈、测试、CI、文档、依赖锁定与待办标记，并给建议入口。开发新系统或接手陌生项目时先跑它。
- `forge_catalog` — 列出阶段、工具与已安装技能，确认「现在该用哪个」。
- `forge_skill` — 按名读取某个技能的完整正文，需要方法论细节时用。

## 用法

1. 开发新系统：`forge_assess` → `forge_spec` → `forge_plan` → `forge_build` → `forge_verify` → `forge_review` → `forge_ship`。
2. 只修 bug：`forge_verify` → `forge_review`。
3. 只做评审：`forge_review`（可传 `focus` 前的阶段说明）。
4. 不记得技能名：`forge_catalog`，再 `forge_skill` 取正文。

## 边界

- 阶段工具只返回流程契约与模板，**不自动改代码**；写文件、跑命令仍由 agent 用常规工具完成。
- `forge_skill` 依赖 mont-forge 插件已安装并注册技能；没装时只有流程，没有正文。
- `forge_assess` 只读扫描，跳过 `node_modules`、`.git`、`dist` 等目录，最多 4000 个文件。
- 阶段划分来自 mont-forge 的 `using-agent-skills` 生命周期，未偏离原始技能内容。

## 卸载

在「插件」里关闭或移除 `Mont Forge 开发流水线` 即可，不影响 mont-forge 本身的技能。
