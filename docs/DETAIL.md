# Mont Forge

45 个生产级工程技能 + 9 个开发全流程工具，一个包全部提供。

## 解决什么问题

AI 编码代理的常见断层：**有技能没流程，或有流程没正文**。

- 45 个技能各自是一份「说明书」，但用户要记住名字，模型还得自己判断该不该加载；
- 一套流水线工具能强制走「规格 → 计划 → 实现 → 验证 → 评审 → 交付」，但如果技能正文在另一个包里，`forge_skill` 就会落空。

本包把两者合到一起：**一次安装，工具与正文都在**。

## 九个工具

| 阶段 | 工具 | 产出 |
|------|------|------|
| 需求 → 规格 | `forge_spec` | 规格文档、验收标准、非目标、质量门槛 |
| 规格 → 计划 | `forge_plan` | 任务清单、阻塞边、关键路径、首个小切片 |
| 实现 | `forge_build` | 可运行的小切片与对应测试 |
| 验证 | `forge_verify` | 复现记录、根因、回归测试、验证证据 |
| 评审 | `forge_review` | 五轴结论、分级问题清单、必修复项 |
| 交付 | `forge_ship` | 提交历史、CI 结果、文档、监控、回滚预案 |

辅助工具：

- **`forge_assess`** — 扫描项目目录，报告技术栈、测试、CI、文档、依赖锁定与待办标记，并给出建议的流水线入口。开发新系统或接手陌生项目时先跑它。
- **`forge_catalog`** — 列出阶段、工具与已装技能，确认「现在该用哪个」。
- **`forge_skill`** — 按名读取某个技能的完整正文。

每个阶段工具返回：

1. 阶段目标
2. 要加载的技能（带中文一句话说明）
3. 步骤清单
4. 本阶段必须产出
5. **退出标准**（不满足不进入下一阶段）
6. 产出模板（Markdown，可直接填）
7. 下一步入口

## 用法

完整开发一条链路：

```
forge_assess → forge_spec → forge_plan → forge_build → forge_verify → forge_review → forge_ship
```

其他场景：

- 只修 bug：`forge_verify` → `forge_review`
- 只做评审：`forge_review`
- 不记得技能名：`forge_catalog`，再 `forge_skill` 取正文
- 想知道项目现状：`forge_assess`

## 边界

- 阶段工具只返回流程契约与模板，**不自动改代码**；写文件、跑命令仍由 agent 用常规工具完成。
- `forge_assess` 只读扫描，跳过 `node_modules`、`.git`、`dist` 等目录，最多 4000 个文件、深度 4 层。
- 阶段划分来自 `using-agent-skills` 的生命周期，未偏离原始技能内容。
- 在 DSH 中**不要**同时用插件与原生技能目录两套，文件系统层会遮蔽插件的同名技能。
