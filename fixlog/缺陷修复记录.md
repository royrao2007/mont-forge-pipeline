#### B01-1 · 近义技能双源

- **编号**：B01-1
- **发现来源**：本批清单核对（技能清单中同时出现 `doc-as-map` 与 `docs-as-map`）
- **问题描述**：两个技能名不同但语义几乎相同，均为「文档即地图」约束。同时存在会让模型随机选中其一，且两者的章节结构、验收标准措辞不一致，出现两种说法并存，违反待立铁律 3 的精神。
- **根因**：分两次创建、命名未统一，未做去重即各自落盘。
- **修改涉及的文件与函数**：
  - 新建 `skills/doc-as-map/SKILL.md`（项目内唯一权威版本，合并两者内容并补齐「功能索引表」「批次索引表」「执行要点」）
  - 删除 `F:\DSHDesktop\dsh-home\skills\doc-as-map\SKILL.md`（6089 字节）
  - 删除 `F:\DSHDesktop\dsh-home\skills\docs-as-map\SKILL.md`（3672 字节）
  - 删除前已备份至 `D:\temp\skill-backup-20261125-162054\`
- **验证方式**：重新枚举技能清单，确认 `doc-as-map` 与 `docs-as-map` 均不再出现，且插件内 `skills/doc-as-map/SKILL.md` 存在。
- **日期**：2026-11-25
- **状态**：**已修**

#### B01-2 · 技能不在项目内

- **编号**：B01-2
- **发现来源**：本批清单核对（两个技能均位于 `%DSH_HOME%\skills\`，`git ls-files` 无匹配）

- **修改涉及的文件与函数**：`skills/doc-as-map/SKILL.md` 落入插件包内；随插件经 `ctx.skills.registerProvider` 进入技能目录。
- **验证方式**：`Test-Path skills/doc-as-map/SKILL.md` 为 True；技能清单可解析到 `doc-as-map`；`git status` 可见该新增目录待提交。
- **日期**：2026-11-25
- **状态**：**已修**

#### B01-5 · 打包清单与 fixlog 的关系核查

- **编号**：B01-5
- **发现来源**：落地时的风险核查（新增强制文件是否会被 `npm pack` 收录）
- **问题描述**：`package.json` 的 `files` 未列 `fixlog`；若把台账与架构文档打进 npm 包，会把本项目的内部开发文档分发出去，与既定推送纪律冲突（只推代码与面向用户的说明性文档，不推内部开发文档）。
- **根因**：`files` 白名单按「运行所需」设计，而 `fixlog/` 属于仓库内工程文档，运行不需要。
- **修改涉及的文件与函数**：**不修改 `files`**，`fixlog/` 保持在仓库内但不入 npm 包。
- **验证方式**：`npm pack --dry-run` 的文件清单中不出现 `fixlog/`；仓库内 `git ls-files fixlog` 可见三份文件。
- **日期**：2026-11-25
- **状态**：**已修**（按「不进包」的结论落实）

#### B01-6 · 验收校验器误报（自测过程中发现）

- **编号**：B01-6
- **发现来源**：本批验收自测第 4 条（「清单条目数 = 记录条目数，且每条有终态」）
- **问题描述**：首次运行校验脚本得到「有终态条数 = 6」，而记录节只有 5 个，判定 FAIL。
- **根因**：校验脚本用全文正则匹配 `**状态**：**已修**`，把本文件末尾「记录格式说明」段里的**格式模板行**
  （`- **状态**：**待修** / **已修** / **不修**（附理由）`）也算成了真实条目。属**校验器缺陷**，非台账内容缺陷。
- **修改涉及的文件与函数**：`D:\temp\verify-acceptance.cjs`（未入库，临时脚本）→ 改为按 `#### B01-N ·` 切节，
  只在每节正文内、且截断到下一个 `## ` 之前统计状态行。台账内容本身未改动。
- **验证方式**：修正后复跑，输出 5 个记录节全部带终态、判定 PASS；并单独断言模板状态行位于
  「记录格式说明」段内（位置正确，非真实条目）。
- **日期**：2026-11-25
- **状态**：**已修**
